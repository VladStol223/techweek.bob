What the Engineering Audit Skill Does (9 Stages)

A single /engineering-audit command kicks off a structured 9-stage workflow that Bob runs autonomously. No templates to fill in. No checklist to follow manually. Bob does the work and reports findings in a structured format you can act on immediately.

The 9 Audit Stages Bob Runs Autonomously
Stage 1 — Repository Discovery
  Maps every layer: frontend, backend, DB, auth, tests, CI/CD, secrets.
  Produces a full Architecture Map before touching source code.

Stage 2 — Technical Audit
  Opens source files. Classifies every finding: Critical, High, Medium, Low,
  False Positive, or Product Decision Required.
  Every finding includes: location, steps to reproduce, root cause, fix, effort.

Stage 3 — Product Decision Gate
  Any finding that requires a business decision is escalated here.
  Bob presents options, tradeoffs, and a recommendation. Waits for your input.

Stage 4 — Remediation
  Implements the smallest safe fix for every Critical and High finding.
  Adds regression tests where feasible. Marks each finding [FIXED].

Stage 5 — Independent Verification
  Acts as a new auditor who has never seen the code.
  Re-opens every file. Verifies each fix with a source-code excerpt.

Stage 6 — Validation
  Runs: type check, lint, production build, unit tests, integration tests.
  Reports each check as [PASS], [FAIL], or [SKIP] with explicit reason.

Stage 7 — First-Time User Journey Audit
  Traces every user flow as a new user who has never seen the product.
  Identifies dead ends, false success messages, missing recovery paths.

Stage 8 — Beta Readiness Triage
  Classifies every open finding: Must Fix / Should Fix / Post-Beta / Known Dependency.
  Gives a recommended fix sequence.

Stage 9 — Release Report
  Produces a complete release report.
  Concludes with: Go / Go With Conditions / No-Go and the reasoning.
